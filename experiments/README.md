# `experiments/` — feature engineering & modeling sandbox

Standalone surface for experimenting on the prebuilt feature matrix without touching the ingestion / API / infra scaffolding under `src/ml_uspto/`. Self-contained: open the notebook, run top to bottom.

## Layout

```
experiments/
└── notebooks/
    └── 01_getting_started.ipynb     # end-to-end: load → split → CV → evaluate → override
```

All helpers (data loaders, `TrainingConfig`, `run_training` orchestrator, plot fns) are defined as cells in the notebook itself. The only imports from `src/ml_uspto/` are the leakage-load-bearing primitives: `build_pipeline`, `time_split`, `time_series_cv`, `evaluate_model`, `MODELS`, `FrequencyEncoder`, `PriorEncoder`. Modify any of the inline helpers in place — that's the point.

## Setup

```bash
pip install -e .          # makes ml_uspto importable
jupyter notebook
```

Required parquets in `data/processed/`:

| Path | What it is | Generated by |
|---|---|---|
| `features.parquet` | model-ready feature matrix (one row per trial, T₀-clean) | `python drivers/run_features.py` |
| `joined_trials.parquet` | master joined frame (raw cols + label + T₀) | `python drivers/run_join.py` |

If empty: run the upstream pipeline (slow, API-bound first time — see `docs/engineering/pipeline.md`) or copy the parquets from someone who already did.

## Notebook structure

| Section | What it does |
|---|---|
| 1. Imports | Production primitives (`build_pipeline`, `time_split`, encoders, `MODELS`, …) |
| 2. Inline helpers | `load_features`, `load_joined`, `merge_features_with_labels`, `TrainingConfig`, `TrainingResult`, `run_training`, `plot_roc`, `plot_confusion`, `plot_feature_importance` |
| 3. Load the data | `features = load_features(); joined = load_joined()` |
| 4. Quickstart | One-liner end-to-end via `run_training(config)` |
| 5. Step-by-step | Same logic peeled into cells: merge → split → CV → refit → eval → plots |
| 6. Override the estimator | `estimator_factory` callable + local `MODELS` dict pattern |
| 7. Override the preprocessor | Build a custom `ColumnTransformer`, wrap in `Pipeline`, run CV |
| 8. Compare estimators | Side-by-side CV on RF vs HGB |

## Hard rules

- **Don't write back into `src/ml_uspto/`** from the notebook — that's production. Promote experiments to `src/` only after they earn their keep.
- **Use `build_pipeline(...)` not raw estimators** — leakage discipline lives in the preprocessor; bypassing it gives optimistic numbers that won't survive deployment.
- **Use `time_split` and `time_series_cv`** — random K-fold leaks future cancellation rates into past predictions.
- **Keep `petition_filing_date` and `patent_number` in `X`** — `PriorEncoder` reads them. Other branches' selectors ignore them; `remainder="drop"` strips them from the final design matrix.
